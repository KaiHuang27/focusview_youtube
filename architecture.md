# Architecture

FocusView is a lightweight browser extension that runs only on YouTube pages and applies local CSS transforms to the active video player.

## Runtime

- `manifest.json` defines the Chrome Web Store extension metadata, long searchable product name, toolbar popup action, YouTube content script match, icon assets, and runtime files with only the `storage` permission for local support reminder state.
- `popup.html` and `popup.css` provide the Chrome and Edge toolbar popup with the same compact FocusView identity, zoom mode hint, store-specific rating link, Ko-fi support link, and macOS-style light/dark presentation as Safari, with only the shortcut key label and rating destination adjusted for Chromium browsers.
- `src/content.js` owns the YouTube player integration, toolbar UI, pointer and wheel interactions, Zoom mode-only player wheel blocking, Zoom mode-scoped window/document fallback for Safari with event-path, pointer-state, and player-bounds hit testing, one accumulating wheel animation controller, 30 fps auxiliary wheel UI updates, batched slider updates, watch-page-only player structure observation, ResizeObserver and fullscreen-triggered transform refresh without frame retry loops, Zoom mode-only pointer tracking and player wheel binding, single-timer transient-control activity tracking, one geometry snapshot per transform frame, active-video CSS-variable transform writes, native play/pause preservation, drag gesture handling, delayed pointer single-click arbitration, immediate keyboard toggling, double-click reset, explicit Fill and Reset settings actions, and player state reset triggers.
- `src/transform-state.js` contains the shared transform state helpers used by the content script and tests, including viewport-centered zoom for controls, fine-grained delta-aware cursor-centered wheel zoom with a 0.0007 sensitivity and 100-pixel delta cap, integer user-facing percentage formatting, player bounds and Zoom mode-aware fallback listener decisions, player-bounds wheel hit testing, elapsed-time-based wheel animation steps, cover zoom calculation for Fill, and full transform reset state.
- `src/overlay.css` contains the extension UI styling and video transform presentation, including shared menu alignment and typography.

- Both toolbar popups use one footer sentence: “Enjoying FocusView? Rate us or buy me a coffee.” The Ko-fi link opens `https://ko-fi.com/kodingai` in a new tab with `noopener noreferrer`; it adds no scripts, permissions, or background network requests. The README uses the same “Buy me a coffee” wording and destination, explains that support is optional, and retains the contact email separately.

## Support Reminders

- `src/support-background.js` serializes extension messages across tabs, persisting only `{ count, interval, laterCount, supported }` under `supportPrompt` in `storage.local`. Each off-to-on Zoom mode transition increments the count. Reaching the saved interval (20 by default) resets the count and requests a popup. Closing preserves the current interval. The footer action (`support:later`) resets the count and increments `laterCount`, capped at three: the first press sets an interval of 60, and subsequent presses set 100. Rating or coffee links send `support:reset`, resetting the count and interval to 20 while preserving `laterCount` and setting `supported` to true. The flag records a link click, not a completed review or payment. When `laterCount` is three and `supported` is true, all subsequent support messages return without changing state or showing a prompt. These two conditions may be reached in either order. State survives background and browser restarts. There is no legacy migration or interval-based inference of past clicks: valid saved intervals (20/60/100) are retained, invalid or missing intervals default to 20, missing click history defaults to zero/false, and invalid activation counters restart at one. Existing usage before this feature is not counted. Storage errors fail silently without interrupting zoom.
- Chrome uses an MV3 service worker; Safari uses a nonpersistent background script. Both load `src/support-prompt.js` before the content script. Background restarts reload state from storage; no analytics or network requests are added.
- The support card uses a 36px existing FocusView icon beside its heading, the thank-you copy “Thanks for watching with FocusView! Your support helps me keep making it better.”, equally styled “Rate FocusView” and “Buy me a coffee” actions with 16px Lucide star/coffee SVGs, inherited text color, 2-unit strokes, and a 6px icon-to-label gap. Icons are decorative (`aria-hidden`, non-focusable) so link names remain unchanged; both actions share normal, hover, and focus treatments. The ISC attribution is bundled in `src/LUCIDE-LICENSE.txt`. It also uses a single-row footer: “Already supported?” beside a “Don’t remind me again” button distinguished by text color without an underline. The footer label and description share `--ytvt-support-secondary` in both themes; the button uses blue to signal interaction and inherits the footer typography. Type sizes remain 20px for the heading, 14px for the description and main actions, and 12px for the footer. The card uses 24px padding, 12px header/action/footer spacing, and 16px between description and actions. The footer wraps only when the available width cannot fit both labels. The footer button keeps its current wording and closes the dialog while progressing reminders to 60 and then 100 activations; its tooltip explains the schedule and the combined condition for permanent suppression. The footer button participates in the keyboard focus loop. Its compact layout has a subtle border, shorter spacing, and a native modal dialog, accessible labels, focus containment and restoration, × and Escape dismissal, responsive light/dark styling that follows the system preference via `prefers-color-scheme`, with an explicit dialog `color-scheme` and matching text, button, hover, and keyboard-focus colors (without brightness filters or a preferred action), and safe external links. It is attached inside the current fullscreen element when applicable. While open, Zoom mode shortcut and wheel handlers are suspended. Chrome links to Chrome Web Store reviews, Safari to App Store reviews; both use the existing Ko-fi destination. The toolbar popup remains available independently. Only `icons/icon-48.png` is exposed as a web-accessible resource, restricted to YouTube, so the content-script dialog can load the bundled logo.
- `src/support-prompt.test.js` covers default thresholds, repeated 60/100-activation reminders, persistence, concurrent updates and action ordering, rating/support reset to 20 with preserved footer history, permanent suppression in either action order across restarts, concurrent suppression actions, invalid state, storage failures, message filtering, branded dialog content and accessible labels, duplicate-dialog prevention, external-action messages, and Chrome/Safari runtime parity. Earlier Chromium fixture smoke checks covered modal interaction, focus, Escape, external links, shared secondary colors, typography and spacing, narrow viewports, fullscreen placement, and the Safari rating destination; those checks do not validate the revised reminder schedule. Native Safari execution is not covered.

## Testing

- `src/transform-state.test.js` verifies transform state behavior, precise capped wheel delta scaling, rapid input accumulation, refresh-rate-independent animation and 100 ms settling, Zoom mode-only player blocking and fallback decisions, player-bounds wheel hit testing, Zoom mode gesture guards, drag-start hold cancellation, and drag-time playback-rate restoration with Node's built-in test runner.

- `src/product-wording.test.js` verifies store-specific manifest metadata and popup rating destinations, compact popup review and Ko-fi links without feedback solicitation, local-storage runtime wiring and support prompt activation, integer user-facing zoom values, user-facing control labels, single-click/double-click arbitration with immediate keyboard activation, accumulating wheel animation wiring, Zoom mode-scoped wheel fallback, watch-page-only player observation, event-driven transform refresh, Zoom mode-only pointer tracking and player wheel binding, shared transform geometry, targeted transform writes, batched wheel and slider UI updates, and safe Safari wrapper resource and message handling across Chrome and Safari resources.

- Run tests with `node --test`.

## Release Packaging

- `scripts/build-release.sh` reads the version from `manifest.json` and writes `dist/focusview-<version>.zip`.
- `package.json`, the Chrome manifest, the Safari extension manifest, and Xcode marketing version stay aligned for each release. Current submitted Chrome version: `1.1.8` (review pending, automatic publication after approval); local Xcode build number: `9`.
- The release zip includes `manifest.json`, `_locales/`, `popup.html`, `popup.css`, `src/content.js`, `src/transform-state.js`, `src/support-background.js`, `src/support-prompt.js`, `src/LUCIDE-LICENSE.txt`, `src/overlay.css`, and `icons/`, which are the runtime files required for Chrome Web Store upload.
- Mac App Store distribution uses the Safari wrapper in `platforms/safari/FocusView`, not the Chrome release zip.
- The README links directly to both supported distribution channels: Chrome Web Store and Apple App Store. Product quality audits and store listing translation details are documented below and in `docs/`, rather than in the user-facing README.

## Safari

- `platforms/safari/FocusView` contains the macOS Safari Web Extension wrapper project.
- The Safari extension manifest mirrors the Chrome manifest version and content script configuration while using the shorter `FocusView - Zoom for YouTube` product name for Apple listing consistency. The compact Safari-style toolbar popup uses explicit macOS-style spacing, dynamic light/dark colors, the FocusView icon, compact FocusView title, a concise YouTube tagline, a zoom mode shortcut hint, an App Store rating link, and a Ko-fi support link.
- The macOS app bundle ID is `com.kodingai.focusview`; the embedded extension bundle ID is `com.kodingai.focusview.Extension`, and the container app uses that exact identifier when opening Safari Extensions settings. The wrapper validates bundled resources and script messages, reports extension-state errors, and keeps the required native handler free of unused payload logging and echo behavior.
- The Xcode project marketing version is kept aligned with the extension manifest version before App Store upload.
